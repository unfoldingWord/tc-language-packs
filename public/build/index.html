Build with it

The packages that make and open packs live in tC Study's repository and are written in TypeScript. They run in a browser on IndexedDB and in Bun or Node on anything with the same small interface.

Read what a pack brings

Show people what a file brings before you open it. readPackManifest reads only manifest.json and throws a readable error when the file is not a pack or is newer than your reader.

import { readPackManifest } from '@bt-synergy/language-pack'

const bytes = new Uint8Array(await file.arrayBuffer())
const manifest = await readPackManifest(bytes)

manifest.kind        // 'language' | 'originals' | 'base' | 'book'
manifest.books       // ['tit'] on a book pack
manifest.requires    // [{ key: 'unfoldingWord/el-x-koine/ugnt', stamp: 'v0.34#…' }]
for (const r of manifest.resources) {
  console.log(r.title, r.stamp, r.rows)  // Texto Puente Literal v42#2026-08-11T12_22_03Z { sot: 5, prepared: 7 }
}

Compare each resource's stamp with your copy before replacing anything: Servos says «newer», «the same» or «older» for each one, and never goes back to an older release.

Open it into your stores

Pass the versions of the code you read with. A pack made with another source version is refused; a derived layer of another version is skipped and listed, for you to rebuild or to say so.

Receipts are written last for each resource, so a pack cut short by a dead battery never marks a resource complete. Opening it again fills what is missing.

import { IndexedDBCacheAdapter } from '@bt-synergy/cache-adapter-indexeddb'
import { IndexedDBCatalogAdapter } from '@bt-synergy/catalog-adapter-indexeddb'
import { importLanguagePack, packTargetFrom } from '@bt-synergy/language-pack'

const stores = {
  cache: new IndexedDBCacheAdapter({ dbName: 'my-app-resources', storeName: 'cache-entries', version: 1 }),
  catalog: new IndexedDBCatalogAdapter({ dbName: 'my-app-catalog', storeName: 'catalog-entries' }),
}

const versions = {
  sot: { usjProcessing: USJ_PROCESSING_VERSION },
  prepared: { scripturePrepare: SCRIPTURE_PREPARE_VERSION },
  quote: { helpsQuote: HELPS_QUOTE_VERSION },
  align: { helpsAlign: HELPS_ALIGN_VERSION },
  text: { helpsText: HELPS_TEXT_VERSION },
}

const result = await importLanguagePack({
  bytes,
  target: packTargetFrom(stores),
  versions,
  overwrite: ['es-419_gl/es-419/tn'],   // replace these resources; keep the rest
  onProgress: (done, total) => bar.set(done / total),
})

result.written            // rows written
result.skippedLayers      // derived layers of another code version
result.skippedResources   // [{ key, why }]
result.originals          // each required original: 'present' | 'in-pack' | 'missing' | 'other-release'

Open the originals pack first: the notes' quotes in a language pack point into it. The version constants come from @bt-synergy/usj-processor and @bt-synergy/resource-pipeline.

Build for the place the file arrives: power lines but no data, a phone with 2 GB of memory, and a stick passed from hand to hand. Read the zip as a stream and write in batches; the Hebrew source alone is 82 MB unzipped.

Make packs

From the command line, in a clone of unfoldingWord/tc-study with bun install done. It runs tC Study's own pipeline in memory, so the rows are byte for byte the ones the app writes. It reads only the public Door43 catalog: what is marked tc-ready for the language, from any owner.

bun packages/resource-pipeline/cli/prepare-language.ts --lang es-419 --out ./packs --books all

  --books all|tit,rut     also write a base pack and one pack per book
  --no-originals          leave out originals.langpack.zip
  --macula <folder>       add MACULA's sentences and referents (Taller's trees/ and referents/)
  --no-lexicons           leave out the language's Hebrew and Greek lexicons
  --lexicons-ref <ref>    read the lexicons at this ref (default master)
  --no-obs                leave out Open Bible Stories and their helps

./packs/es-419.langpack.zip       the whole language, without the originals
./packs/originals.langpack.zip    UGNT and UHB, the same for every language
./packs/es-419-base.langpack.zip  with --books: catalog, TA, TW, OBS, lexicons
./packs/es-419-tit.langpack.zip   with --books: one per book
./packs/es-419.report.json        what was found, built, blocked and packed
import { buildLanguagePack, packSourceFrom } from '@bt-synergy/language-pack'

// From stores your app has already filled:
const source = packSourceFrom(stores)
const titus = await buildLanguagePack({ source, language: 'es-419', kind: 'book', books: ['tit'], versions })
titus.bytes      // the zip
titus.skipped    // resources left out, with the reason

A resource goes in only when its receipt says it arrived whole. The first es-419 run took seven and a half minutes; English does not fit in one process, which is why parts exist.

Download parts

With internet, ask the server for a language's parts list, download the parts you lack into staging, and apply them. The package plans and applies; downloading is yours.

Check that each part's sha256 is its name before you keep it. Run the same sequence at startup with nothing to download: it heals whatever an interrupted run left.

GET https://tc-helps.mcp.servant.bible/v2/packs/f2.0-u2.3.0-p6000230-q9-a12-t1/es-419
GET https://tc-helps.mcp.servant.bible/v2/packs/f2.0-u2.3.0-p6000230-q9-a12-t1/originals/<sha256>
GET https://tc-helps.mcp.servant.bible/v2/packs/parts/<sha256>
import { IndexedDBByteStore } from '@bt-synergy/cache-adapter-indexeddb'
import { REGISTER_PREFIX, applyParts, packTargetFrom, planParts, readRegister, stagingFrom } from '@bt-synergy/language-pack'

const target = packTargetFrom(stores)
const staging = stagingFrom(new IndexedDBByteStore({ dbName: 'my-app-parts' }))
const register = readRegister(await stores.cache.getByPrefix(REGISTER_PREFIX))
const chosen = ['shared', 'book tit', 'book rut']

const plan = planParts({ list, originals, register, chosen, versions })
for (const part of plan.download) await staging.put(part.sha256, await download(part))
const result = await applyParts({ target, staging, plan, list, originals, register, chosen, versions })
AnswerWhat to do
200 + ETagThe current list. Send the ETag as If-None-Match next time.
304Nothing changed.
202 preparingA build is on its way. Ask again after Retry-After.
404 old-compatYour app is older than the packs: ask people to update.
404 no packsThe language has no aligned literal text marked tc-ready.
429, 503Wait as long as Retry-After says, then go on.

Parts are immutable and can be resumed with Range. The full contract is in docs/LANGUAGE_PACKS_INFRA.md of translation-helps-mcp.

Serve answers from views

A server does not need IndexedDB. translation-helps-mcp reads views: plain JSON files per chapter, written from a pack, with each note's words already found in the literal and the simple text. For es-419 its median answer went from 13 ms to 2 ms.

The same views read from a folder would let an assistant answer with no internet.

bun packages/resource-pipeline/cli/mcp-views.ts …   # writes the files below from a pack

v1/es-419/index.json
v1/es-419/notes/TIT/1.json
v1/es-419/word-links/TIT/1.json
v1/es-419/questions/TIT/1.json
// translation-helps-mcp, src/api/routes/packViews.ts
export interface PackViews {
  get(path: string): Promise<unknown | null>   // an R2 bucket in a Worker, a folder in a script
}
{
  "id": "rtc9",
  "reference": "1:1",
  "quote": "κατὰ πίστιν",
  "supportReference": "rc://*/ta/man/translate/figs-abstractnouns",
  "supportReferenceTitle": "Sustantivos abstractos",
  "aligned": {
    "literal": "conforme a la fe",
    "simple": "Dios me envió a enseñar … para que confíe más en él"
  }
}

One note of Titus 1:1 from v1/es-419/notes/TIT/1.json, with its text and a few fields left out. Views have their own schema (schema: 1), which does not change when the code that prepares packs does.

Give it to your agent

An agent skill teaches Claude Code, Codex, Cursor or Gemini CLI what a pack is and how to read one with no internet. It brings a reader that needs only Python: verses, alignments, notes, questions, word links, articles, lexicon entries, and every place a word or an article occurs across books.

Packs are modular, so its answers say which books are not on the device and which pack would bring them.

Download the skill
# Claude Code
/plugin install language-packs --marketplace unfoldingWord/language-packs-site

# Codex, Cursor, Gemini CLI: unzip into your project
.agents/skills/language-packs/SKILL.md
python scripts/langpack.py occurrences originals.langpack.zip es-419.langpack.zip --strong G5485 --text glt

  **Fe** es un sustantivo abstracto. Aquí se refiere al creer o al confiar en Jesús. …

Every place a word occurs comes from the packs' word index, the optional index layer of language packs v3; the reader finds the same places in the original's own words when a pack has no index. The skill's files are also at SKILL.md, and the site's map for agents at llms.txt.
