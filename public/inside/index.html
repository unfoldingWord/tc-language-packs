Inside a pack

A pack is a zip of the rows tC Study keeps in its cache after it has read a language. Open it into the same stores and the app reads it as if it had downloaded and prepared everything itself.

This page goes down the archive one level at a time: the file, its manifest, its rows, the kinds of pack, its versions, and the parts that split a language into small pieces.

The manifest of an English pack of Titus, shortened to one of its resources, with the stamps and versions of the English release of October 2026.

format, formatVersion
What the file is. A reader refuses a pack whose major version is newer than its own.
kind, books
Whole language, originals, base, or the books named here.
requires
The Greek or Hebrew release the notes' quotes were found in. Without it, the quotes wait until the originals pack is opened.
versions
The version of the code that made each layer. A reader with another source version refuses the pack; one with another derived version skips that layer and rebuilds it.
resources
Each resource with its key {owner}/{language}/{id}, its release stamp, how many rows of each layer it brings, and which books its release has.

Six layers of rows

Every row is {"key", "entry"}, raw as the cache keeps it. The first two layers always travel; the other four are built from them, and travel so that a phone never has to build them.

receiptA resource arrived whole, from which release, read with which schema. Written last.resource:{key}Always
sotThe source of truth: each chapter as USJ with its alignment to the original; notes, questions and word links by book; Translation Words and Academy articles; lexicons; MACULAscripture-usj:{key}:{book}:{chapter}

preparedEach chapter ready to draw: light (blocks of text) and full (each word, its occurrence, and the original words it translates)prepared:{type}:{key}:{book}:{chapter}:{light|full}Built

Lexicons (one file per Strong's number, {key}/content/5485.json) and MACULA's sentences and referents ({key}/trees/{BOOK}) travel as resources of their own in the sot layer.

Four kinds of pack

originals

22.9 MB

The Greek New Testament, the Hebrew Bible and MACULA's analysis of both, every book. As a zip it is one file for every language; as parts, each book's original comes with that book, so a team that translates Titus downloads 30 KB of Greek, not the whole Bible.

language

165 MB

Every resource of one language, whole, with its receipts. No originals. All of English: ULT, UST, BSB, T4T, notes, questions, words, links, academy and lexicons.

base

3.7 MB

What every book needs: Translation Words, Translation Academy and the lexicons whole, and the catalog row of each book-scoped resource.

book

0.1–12.7 MB

The texts, notes, questions and word links of the books it names. No receipts: a receipt would claim the whole release.

Three versions, three questions

Can I read this file?

The format version. Only a newer major version is refused.

"formatVersion": "1.1.0"
Is it newer than mine?

Each resource's stamp: its Door43 release tag and when it was published.

"stamp": "v91#2026-09-26T15_45_57Z"
Can I use its rows?

The version of the code that made each layer. These change often.

"helpsAlign": 12

The five code versions and the format make a compatibility key. A server keeps packs under it, and an app asks only for its own.

f1.1-u2.3.0-p6000230-q9-a12-t1

Whole packs of format 1.1 today. Parts lists use format 2.0, so their key starts with f2.0. Built by compatKeyOf in packages/language-pack/src/catalog.ts.

Only what changed comes down

With internet, a language arrives as parts of about 250 KB. When one book changes, a phone downloads that book and nothing else.

Parts: the same rows, cut small

Format 2.0 cuts a language into content-addressed parts, each one gzip of JSONL rows {"layer", "key", "value"}. A parts list names them all; a part whose inputs did not change keeps its hash and is never built or downloaded again.

  "schema": 2,
  "language": "en",
  "compat": "f2.0-u2.3.0-p6000230-q9-a12-t1",

    "bytes": 83567,

The English list (/v2/packs/f2.0-u2.3.0-p6000230-q9-a12-t1/en, 595 parts) with one real entry: the notes of Titus. The list also names its resources, units and originals.

Where the rows go:

  • By book: the text, the original, MACULA, the helps, and their alignments.
  • Translation Words in 8 groups, Academy by manual, all titles together.
  • Lexicons by ranges of 1,000 Strong's numbers.
  • Open Bible Stories ten at a time.

A reader skips a part of a kind, a layer or an index version it does not know, and keeps everything else. That is how a new optional layer can be published without breaking older apps.

What is not settled yet

  • Rows follow the code. A pack is a copy of tC Study's cache, so every change to the code that prepares a layer makes the packs already handed out unreadable for that layer. Between 20 and 24 October 2026 those versions changed five times.
  • No schema. The format is described by TypeScript types; there is no JSON Schema an app in another language can validate against.
  • No signature. Parts are checked by their sha256 when downloaded. A pack passed hand to hand cannot yet prove who made it.
  • A word index is coming. An optional index layer will let an app find a Greek or Hebrew word in every book, even books not on the device.
